# 店舗ごとの営業時間

曜日ごとに開始00:00〜23:59、終了00:00〜24:00を設定する。全店舗共通の既定営業時間は作らない。

| 設定例 | 解釈 |
| --- | --- |
| 09:00〜20:00 | 同日20:00まで |
| 18:00〜05:00 | 翌日05:00まで |
| 05:00〜12:00 | 早朝から正午まで |
| 00:00〜24:00 | 24時間営業 |
| 09:00〜12:30、15:00〜18:20 | 12:30〜15:00は中休み |
| 曜日の営業チェックを外す | その曜日には営業を開始しない |

終了が開始より早ければ翌日まで。同時刻の開始・終了は拒否する。深夜営業は開始した曜日に属する。例えば月曜18:00〜翌05:00は、火曜の営業開始が休みでも火曜05:00まで継続する。曜日をまたぐ重複も拒否し、連続する境界は許可する。最大12時間帯／曜日。

`business_hours` の従来の `{open,close}` と休業の `null` を保持する。複数時間帯は `periods` 配列を追加し、従来のopen/closeには最初の時間帯を保持する。既存施設を一括書換しない。

管理画面の保存・公開条件、公開表・構造化データ、検索、JSTの営業状態、予約可能枠と予約の原子的な作成・変更に同じ時間帯を使用する。中休みをまたぐ予約は受け付けない。終了24:00の時刻計算と隣接日の予約バッファは日付を含めて判定する。店舗の電話予約を手動で登録する既存の権限は維持する。

予約1件の開始と終了は同じ暦日の範囲で管理する。深夜営業の早朝分は翌日の枠となる。スタッフの勤務も暦日ごとの設定が必要。勤務の自動下書きが複数の離れた時間帯を表せない場合、昼休みを埋めた勤務を自動生成せず手動設定を案内する。施設の中休みには、スタッフの勤務が続いていてもネット予約枠を出さない。

祝日カレンダー・特定日の施設休業・診療受付締切を文章から推測して自動設定する機能は含まない。

## 配信と検証

DBのperiod対応読取関数とゲートを先に適用してから、periodを書き込むアプリを配信する。DB変更だけでは施設データは変わらない。アプリを戻す場合も、複数時間帯を保存した施設のデータを失う旧フォームで上書きしないこと。

使い捨てPG17の `supabase/shadow/business-periods-fixtures.sql` はA/B/C・終日・中休みの実予約枠、作成・変更の中休み拒否、翌暦日へのバッファを検証し、すべてROLLBACKする。ブラウザの `e2e/business-periods.spec.ts` は隔離CIでのみ合成の所有者・施設を作り、保存・再読込・無料公開・公開表を確認する。本番顧客の施設・予約は試験に使わない。

## 自動の営業状態を施設ごとに非表示にする

施設設定の「公開ページに『営業中』などの自動表示を出す」をオフにして保存すると、その施設の「営業中・営業時間外・定休日」の自動バッジを表示しない。曜日別の時間表、紹介文、予約の時間帯判定は維持する。初期値はオンで、他施設の選択を変更しない。設定は既存の所有者・管理者権限と原子書込を使用する。

祝日・臨時休業を自動判定する機能はない。曜日別の時間だけでは正確に判定できない施設は、自動表示をオフにし、休診日や受付終了の案内を既存の補足・紹介文に記載できる。診療・受付終了時刻を文章から推測したり、予約機能の利用を求めたりはしない。
