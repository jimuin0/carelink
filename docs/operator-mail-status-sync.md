# 運営メールの配信状況確認

受信トレイを開いた時と「一覧を更新」した時に、保存済みの予約・送信処理を配信サービスへ照会してから、一覧と選択中の返信履歴を読む。定期実行・送信・再送信・取り消しは行わない。

照会は既存の認証、CSRF、運営権限の再確認、原子的なメール操作RPCを使用する。宛先・本文・差出人・返信先・操作タグが一致した証拠だけを保存する。配信時刻の経過を送信完了や配信完了の証拠にしない。

1回の更新で最大2件を照会する。キーセットカーソルは確認不能な処理の先にも進み、古い2件に留まり続けない。残りがある時や照会に失敗した時は未確認と明示し、次の「一覧を更新」で続きを確認する。末尾でカーソルを戻し、次の更新では未確定処理を再確認する。ページを閉じればカーソルは初期化する。確認不能の処理も元データのまま保持する。

一覧と返信履歴は、同じ更新世代の照合完了を待つ。選択中の送信済みメールには確認済みの状態だけを反映し、新しい版や下書き・未保存本文を古い状態で上書きしない。ログへ宛先・本文・秘密情報を出さない。

本番受入では、既存の運営アカウントでログインし、実行済みメールの状況確認だけを行う。顧客への新規送信や取り消しを試験に使わない。隔離CIでは実メール送信の資格情報を渡さず、実Auth・API・DBでキーセットの構文と権限制御を確認する。
