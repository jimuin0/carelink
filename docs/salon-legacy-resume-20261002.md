# 旧掲載フォームの保全・再開

## 実装と境界

- 入力と元画像を利用者の操作でローカル JSON ファイルに保存・復元する。画像のバイト列と7枠の順序を保ち、各画像と全体の SHA-256、サイズ、形式を検証してから一括復元する。署名は破損検出用で、送信履歴の証明ではない。
- 下書き自体に期限を設けない。サーバー側の準備・証明の期限、認可、容量制限を延長・緩和しない。認証情報、署名 URL、同意、送信受付情報はバックアップしない。
- 復元は先頭の確認段階に戻り、同意と「未送信」の確認をやり直す。準備済み・送信開始済み・結果不明の処理を復元で上書きしない。別タブや過去の送信状況はファイルだけでは判定できず、結果不明の場合は受付状況の確認が必要。
- 修正後の V1 フォームで、実際の Storage 権限拒否が掲載 API の送信前に発生した場合のみ、明示操作で署名付きアップロードへ再試行できる。同じ入力・元画像を使い、サーバーの機能フラグに従う。通信失敗を成功扱いしない。
- 元画像は自動的にサーバーやブラウザ永続ストレージへ退避しない。ダウンロードには個人情報・写真が含まれることを画面で伝える。

## 検証方法

元の main `3d8e6c53` の RegisterForm を固定 fixture として保持する。JSDOM の負例は、旧実装が権限拒否後に開いた画面内の入力・File を保持する一方、再マウントでは復旧できず、署名付き再試行もないことを確認する。これは実ブラウザでの旧配信物アップグレード証明ではない。

修正後 V1 を固定する隔離 Playwright テストは、正式切替後の RLS 拒否、署名取得失敗と通常再試行、元画像の一致、保存・再読込・8日後の復元、同意のやり直し、写真編集後の戻る・進む操作と保存内容を確認する。ブラウザの時計変更は下書きの期限非依存性の検証であり、サーバーの証明期限延長の証明ではない。外部メール・LINE送信を使用しない。

## 本番切替の未解決条件

既に開かれた未修正 JavaScript に新しい保存・復元機能を遡って追加することはできない。旧タブの存在や利用者が元画像を回収できることは、本検証だけでは保証しない。一定時間の待機や新規 intent がゼロであることを旧フォーム消滅の証拠にしない。

本番の匿名アップロード停止、容量設定、正式 migration の適用は別途承認が必要。先に保全機能を配信する案を具体化しても、既存の未修正タブについて利用者への回収手順・対象・確認方法が定まるまでは切替完了と扱わない。本変更では本番設定・機能フラグ・権限・データを変更しない。
